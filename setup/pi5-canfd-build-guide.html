SystemCore Clone: Pi 5 + CAN FD HAT

Build a custom SD card from the SystemCore base image. No Raspberry Pi OS needed.

1. Downloads

  • Raspberry Pi Imager Flashes the SD card.
  • SystemCore base image: Limelight beta17 (233) Download limelightsystemcorebetacm5-limelightosr-2027.0.0-beta17.zip (~810 MB). The other assets (.llupdate, toolchain, kernel source) are not flashable images.
  • canivore-usb-kernel_1.18_aarch64.ipk CANivore driver 1 of 2. Only needed if you use a CANivore.
  • canivore-usb_1.16_aarch64.ipk CANivore driver 2 of 2. Only needed if you use a CANivore.
  • WPILib 2027.0.0-alpha-7 for Mac (Arm) Installs on your computer, not the Pi. Run xcode-select --install first. Other platforms: release page.
  • FIRST Driver Station alpha 7, and Elastic alpha 9 or newer Required by WPILib alpha 7 (see its release notes).
  • This repo (cloned locally) You need fd/config_with_fd.txt, the fd/systemcore-can-fd-setup/ folder, and project_examples/.

2. Steps

  1. Flash the SD card

    In Raspberry Pi Imager: choose Raspberry Pi 5, then under OS pick Use custom and select the SystemCore base image. Pick your SD card and write it. Skip any OS customisation prompts.

  2. Boot the Pi

    Insert the SD card with the CAN FD HAT seated, power on, and wait about a minute.

  3. Join the Pi's Wi-Fi and open the dashboard

    Network SYSTEMCORE, password PASSWORD (upper case). Then open http://172.30.0.1 or http://robot.local. These only load while you're on the Pi's network.

  4. Open the Terminal app

    It's in the web dashboard. The commands in steps 5 and 7 run here.

  5. Replace the boot partition's config.txt

    This enables the HAT's two mcp251xfd CAN controllers.

    sudo mkdir -p /mnt/hardware_boot
sudo mount /dev/mmcblk0p2 /mnt/hardware_boot
sudo nano /mnt/hardware_boot/config.txt

    Delete everything in the file, then paste the entire contents of fd/config_with_fd.txt. Save with Ctrl+O, Enter, Ctrl+X.

    sudo umount /mnt/hardware_boot
sudo reboot

  6. Copy the installer to the Pi

    Run on your computer, inside the repo's fd/ folder

    scp -r systemcore-can-fd-setup systemcore@172.30.0.1:/home/systemcore/

    Default login is systemcore / systemcore (per the repo README).

  7. Run the installer

    Run on the Pi (terminal app or SSH)

    cd ~/systemcore-can-fd-setup
sudo ./install.sh
sudo reboot

    This installs can-bringup.service: on each boot it names the HAT buses can_s0 and can_s1 at 1 Mbit, creates can_s2 to can_s4 as virtual buses, and loads robot_heartbeat.

  8. Install the CANivore drivers (optional)

    In the web dashboard open the 4th tile and choose "add packages". Drag in canivore-usb-kernel, then canivore-usb, then reboot.

    The repo says the correct order is unclear. If this order fails, try the reverse.

  9. Verify

    ip -br link show | grep can_s           # can_s0 and can_s1 up/physical, can_s2-4 virtual
ls /dev/mrccan/                         # enable interface files should be listed
systemctl is-active can-bringup robot   # both should print "active"
    The CAN setup scripts are untested on beta17. WPILib needs can_s0–can_s4 and can_d0–can_d19 to exist. If the robot program logs ioctl(SIOCGIFINDEX) for CAN can_dX failed, the image isn't creating the can_d* interfaces. Check with ip -br link show | grep can_d.

  10. Update motor controller firmware

    In Phoenix Tuner X, connect to the robot and flash firmware that matches the Phoenix 6 API version in the project (26.70.0-alpha-2 in the examples). A mismatch shows up as "API too old / CAN frame too-stale".

  11. Deploy code

    With WPILib alpha 7, open project_examples/ctre/ctre-commands-v2 or ctre-commands-v3 and deploy as normal. In code, the HAT buses are new CANBus(CANPort.CAN_S0) and new CANBus(CANPort.CAN_S1).

    Enable from the Driver Station's Enable button. Space and Enter are the e-stop and latch the robot disabled.

Repo inconsistencies to ignore

  • fd/systemcore-can-fd-setup/README.md mentions MCP2515 chips and a folder named systemcore-can-setup. Your HAT uses MCP2517/2518FD chips and the folder is systemcore-can-fd-setup. The scripts and config_with_fd.txt are correct.
  • The "Getting Started" sections in fd/README.md describe the pre-built image path. Ignore them.
